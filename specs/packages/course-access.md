# course-access: 课程观看资格

## 意图

规定现有学堂的观看入口、观看资格、播放地址签发与读取，以及页面续播行为。
观看资格仅要求有效登录会话和课程已发布，不要求报名，也不区分学员与管理员。
账号登录表单、课程编辑和视频制作不在本包范围内。

## 外部行为

### course-access-1

当客户端通过请求边界检查 [[course-access-12](#course-access-12)] 后以 `POST /api/courses/:id/play` 请求新播放地址时，学堂应按有效登录会话 [[course-access-18](#course-access-18)] 和课程当前发布状态决定是否签发：

| 按顺序判定的条件 | HTTP 状态与 JSON 响应 |
| --- | --- |
| 未登录，无论课程是否存在或已发布 | `401`，`{"error":"请先登录后再观看"}` |
| 已登录，课程不存在或未发布 | `404`，`{"error":"课程不存在或尚未发布"}` |
| 已登录，课程已发布，无论用户是学员还是管理员 | `200`，仅含 `url` 和 `expiresAt` |

- 成功响应的 `expiresAt` 为签发时刻加配置的有效期，采用 Unix 毫秒时间戳，默认有效期为 60 秒。
- `url` 为 `/media/:id?expires=<expiresAt>&signature=<signature>`，签名按 [[course-access-19](#course-access-19)] 生成。
- 每次申请均重新判定资格，取消发布后不再签发新地址，签发时不检查视频文件是否存在。

### course-access-2

当浏览器请求 `GET /courses/:id` 时，学堂应按课程发布状态和签发播放地址的同一资格判定 [[course-access-1](#course-access-1)] 返回详情页或错误页：

| 条件 | 结果 |
| --- | --- |
| 课程不存在或未发布，无论是否登录 | `404` HTML 错误页，不显示观看入口 |
| 课程已发布，未登录 | `200`，显示课程介绍、`data-state="login"` 和指向 `/login?next=%2Fcourses%2F:id` 的“去登录”入口，不显示“开始观看”按钮 |
| 课程已发布，已登录 | `200`，显示 `data-state="ready"` 和“开始观看”按钮 |

- 成功返回的页面中视频元素初始隐藏，不含播放地址。
- 登录入口携带当前课程路径，供登录成功后回到本页。

### course-access-3

给定播放地址通过校验 [[course-access-4](#course-access-4)] 且对应课程的视频文件可读取 [[course-access-14](#course-access-14)]，当客户端以 `GET` 或 `HEAD` 读取该地址时，学堂应返回对应视频的 HTTP 响应：

- 地址本身就是授权，无需 Cookie，也不重新检查课程是否已发布；课程取消发布或用户退出登录后，旧地址在到期前仍可读取。
- 响应包含 `Content-Type: video/mp4`、`Accept-Ranges: bytes` 和本次响应范围的 `Content-Length`。
- `HEAD` 使用与 `GET` 相同的状态和响应头，不返回响应体。

| `Range` 情形（文件长度为 `size`） | 结果 |
| --- | --- |
| 无范围、格式无法识别、多段范围、空范围或结束位置小于起始位置 | `200`，完整文件 |
| `bytes=start-end` | `206`，含首尾的字节段，`end` 超过文件末尾时截断 |
| `bytes=start-` | `206`，从 `start` 到末尾 |
| `bytes=-suffix`，`suffix > 0` | `206`，最后 `suffix` 字节，最多返回整个文件 |
| 起始位置不为安全整数或不小于 `size`，或 `bytes=-0` | `416`，`Content-Range: bytes */size`，JSON 错误“请求的视频范围无效” |

- `206` 响应包含 `Content-Range: bytes start-end/size`。

### course-access-4

当客户端以 `GET` 或 `HEAD` 读取编号合法的 `/media/:id` 地址时，学堂应先验证签名、再验证到期时间，未通过时不返回视频内容：

| 条件 | 结果 |
| --- | --- |
| `expires` 不是 1～15 位十进制数字，或 `signature` 不是 64 位小写十六进制字符串，或与该课程及到期时间的预期签名不符 [[course-access-19](#course-access-19)] | `403`，错误“播放地址无效” |
| 签名有效，但 `expires` 小于或等于当前 Unix 毫秒时间戳 | `410`，错误“播放地址已过期，请重新获取” |

- 校验使用查询参数中第一个同名值，缺失值按空字符串处理。
- `GET` 错误响应为仅含 `error` 的 JSON 对象。

### course-access-5

当客户端绕过签名地址，按视频文件名或目录穿越路径直接请求视频时，学堂应拒绝返回视频内容：

- `/media/python-basics.mp4`、`/media/`、`/assets/../media/python-basics.mp4` 和 `/assets/media/python-basics.mp4` 均返回 `404`。
- 静态资源入口只服务 `public/` 内允许的类型，不公开 `media/` 中的 MP4 文件。

### course-access-6

如果课程页已取得播放地址且未在续签中、距上次成功播放不足两次续签尝试，当视频元素触发媒体加载错误时，课程页应通过签发接口重新申请地址 [[course-access-1](#course-access-1)] 并尝试恢复进度：

- 无论加载错误是否由地址到期造成，均执行此流程。
- 记录视频当前进度与最近一次正数进度的较大值，替换地址后在 `loadedmetadata` 事件中恢复该进度。
- 出错前处于希望播放的状态时尝试继续播放，否则保持暂停。
- 续签期间不重复申请；收到 `playing` 事件后清零续签失败计数。

### course-access-12

当客户端请求签发或读取播放地址时，学堂应先执行对应请求的边界检查，再进入观看资格或地址校验：

| 按执行顺序的检查 | 不通过的结果 |
| --- | --- |
| `POST` 签发请求携带的 `Origin` 必须等于 `http://` 加请求的 `Host`，未携带时允许 | `403`，JSON 错误“请求来源不受信任” |
| `POST` 签发请求的 `Content-Type` 媒体类型必须为 `application/json`，忽略大小写并允许参数 | `415`，JSON 错误“请用 JSON 提交，并设置请求头 Content-Type: application/json” |
| 签发和媒体读取的课程编号须匹配 `[1-9]\d{0,15}` 且为安全整数 | `404`，JSON 错误“内容不存在” |

- 本包的 HTTP 用例均通过服务支持的本机 `Host` 访问。
- 签发接口不读取请求体，不以请求体中的用户、课程或资格字段作判断。

### course-access-13

如果详情页显示“开始观看”按钮，当用户点击该按钮时，课程页应通过 `POST /api/courses/:id/play` 取得地址 [[course-access-1](#course-access-1)] 后才开始播放：

- 请求期间禁用按钮并显示“正在准备视频…”。
- 成功后把 `url` 赋给视频元素，显示并聚焦视频，把播放面板状态设为 `playing`，尝试调用视频播放。
- 浏览器拒绝播放调用时显示“视频已就绪，请点击播放按钮开始观看。”。

### course-access-14

给定媒体请求已通过地址校验 [[course-access-4](#course-access-4)]，当学堂定位对应课程的视频文件时，学堂应仅允许读取配置的媒体目录内该课程当前绑定的普通文件：

- 课程不存在、视频文件名不匹配 `^[a-z0-9][a-z0-9-]{0,80}\.mp4$`、文件不存在或不是普通文件时，返回 `404` 和 JSON 错误“视频不存在”。
- 此检查使用课程当前绑定的视频文件，不将签名绑定到签发时的文件名。

### course-access-15

如果课程页申请初始地址或续签地址失败，当页面收到申请错误时，课程页应显示错误并按 HTTP 状态处理：

| 条件 | 结果 |
| --- | --- |
| `401` | 显示“登录状态已失效，正在前往登录页…”，约 1200 毫秒后跳转至携带当前课程路径的 `/login?next=…` |
| 其他接口错误 | 显示接口的错误消息 |
| 网络请求失败 | 显示“网络连接失败，请确认服务仍在运行后重试。” |

- 初次申请失败时恢复“开始观看”按钮的可用状态和文字，并聚焦按钮。

### course-access-16

如果已有播放地址、未在续签中且距上次成功播放已尝试两次续签，当视频元素再次触发媒体加载错误时，课程页应停止自动申请地址并显示失败提示：

- 提示为“视频加载失败，请刷新页面后重试。”。

## 内部行为

### course-access-17

当课程页计算观看入口状态或签发接口判断观看资格时，学堂应调用 `src/playback.js` 中的同一个 `checkWatchEligibility`，按先登录、后课程发布状态的顺序实现资格判定 [[course-access-1](#course-access-1)]。

### course-access-18

当观看入口或签发接口解析请求的登录身份时，会话解析应仅将 `academy_session` Cookie 中的 64 位小写十六进制令牌识别为已登录用户，且其 SHA-256 散列必须匹配数据库中尚未到期并关联现存用户的会话：

- 到期时间须严格大于当前 Unix 毫秒时间戳；缺失、格式错误、未知、已删除或已到期的会话均视为未登录。
- 退出登录及换账号登录均删除请求携带的旧会话，旧令牌不能再次取得新播放地址。

### course-access-19

当学堂签发或验证播放地址时，签名处理应使用数据库设置 `playback_secret` 为密钥，对规范化的十进制课程编号与到期毫秒时间戳组成的 `courseId:expiresAt` 字符串计算 HMAC-SHA256，输出小写十六进制签名并以常数时间比较预期签名与请求签名。

## 验证

### course-access-7

当对真实学堂执行签发集成测试时，测试应通过 HTTP 请求核对签发决策 [[course-access-1](#course-access-1)]：

- 无会话请求已发布、草稿和不存在课程均为 `401`；学员和管理员请求草稿或不存在课程均为 `404`，拒绝响应不含地址。
- 学员和管理员请求已发布课程均为 `200`，响应键恰为 `url`、`expiresAt`，地址参数匹配响应到期时间，默认有效期为 60 秒，配置较短有效期时按配置到期。
- 获取地址后取消发布，再次申请为 `404`；更改为缺失的视频文件仍可签发。
- `test/watch.test.js` 已覆盖学员签发、拒绝、默认及短有效期、取消发布和缺失文件签发；其他矩阵情形需补验。

### course-access-8

当对真实学堂执行课程页集成测试时，测试应以未登录、学员和管理员身份访问已发布、草稿和不存在的课程，核对详情页状态、入口、登录回跳路径和页面不含播放地址 [[course-access-2](#course-access-2)]，并以白盒检查确认页面与接口调用同一资格函数 [[course-access-17](#course-access-17)]：

- `test/watch.test.js` 和 `test/catalog.test.js` 已覆盖访客与学员的已发布页面、访客草稿页及登录回跳参数；其他矩阵情形需补验。

### course-access-9

当对真实学堂执行媒体读取集成测试时，测试应使用实际签发的地址及篡改地址核对视频响应与授权校验：

- 不带 Cookie 执行完整 `GET`、`HEAD`、闭合范围、开放范围、后缀范围、超长范围、无效格式、多段范围和不可满足范围，逐项核对状态、响应头及实际字节 [[course-access-3](#course-access-3)]。
- 逐项篡改签名、到期时间、课程编号，省略参数，使用非数字到期时间、错误长度或大写签名，并组合无效签名与已过期时间，断言先返回 `403` 且没有视频 [[course-access-4](#course-access-4)]。
- 签发后取消发布或退出登录，断言旧地址到期前仍可读取 [[course-access-3](#course-access-3)]。
- 使用临时数据库的真实密钥独立计算 HMAC 并核对签发签名，白盒核对比较方式 [[course-access-19](#course-access-19)]。
- `test/watch.test.js` 已覆盖无 Cookie 的完整读取、普通范围、后缀范围、开放范围、完整 `HEAD`、越界及基本篡改；其他矩阵情形需补验。

### course-access-10

当对真实学堂执行素材隔离集成测试时，测试应逐一请求文件名、目录路径、目录穿越和静态资源路径，断言 `404` 且无视频内容 [[course-access-5](#course-access-5)]：

- `test/watch.test.js` 已覆盖文件名、媒体目录和目录穿越；静态资源中的 MP4 路径需补验。

### course-access-11

当对真实学堂执行续播系统测试时，测试应分别验证服务端过期与浏览器恢复行为：

- 配置短有效期，取得真实地址并在过期后读取，断言 `410`；另以真实密钥构造到期时间等于检查时刻的地址并核对到期边界 [[course-access-4](#course-access-4)]。
- 浏览器加载真实课程页，记录正数播放进度，等待地址过期并触发后续媒体请求，断言页面自动申请新地址，加载元数据后恢复进度，并根据原播放或暂停意愿决定是否续播 [[course-access-6](#course-access-6)]。
- 另以非过期的媒体错误触发续签，断言相同恢复行为；重复错误时断言最多两次自动申请、第三次错误显示失败提示，成功 `playing` 后重新计数 [[course-access-6](#course-access-6)] [[course-access-16](#course-access-16)]。
- `test/watch.test.js` 仅覆盖过期后 `410`、显式重新申请和后续字节读取；到期边界与浏览器自动续播、重试上限需补验。

### course-access-20

当对真实学堂执行请求边界集成测试时，测试应以跨源 `Origin`、缺失或错误媒体类型、带参数的 JSON 媒体类型、非法编号及含伪造身份的请求体请求播放接口，核对检查顺序、错误响应及请求体不改变资格判定 [[course-access-12](#course-access-12)]：

- 非法编号矩阵包含 `0`、`01`、负数、非数字、超过 16 位及超过安全整数范围的值，覆盖签发和媒体读取。
- `test/server.test.js` 已覆盖通用跨源与媒体类型检查；播放路由专属矩阵需补验。

### course-access-21

当对真实学堂执行视频定位集成测试时，测试应先取得有效地址，再分别移除课程、设置非法文件名、设置缺失文件或目录，断言读取返回 `404` 和“视频不存在”，并将课程改绑为另一合法视频以核对读取当前绑定的内容 [[course-access-14](#course-access-14)]：

- `test/watch.test.js` 已覆盖缺失文件；其他情形需补验。

### course-access-22

当对真实学堂执行会话集成测试时，测试应分别携带有效、缺失、格式错误、未知、已删除、恰好到期及已过期的 Cookie 请求课程页与签发接口，核对观看身份，并在退出及换账号后重放旧令牌确认失效 [[course-access-18](#course-access-18)]：

- `test/auth.test.js` 已覆盖真实会话解析、过期、退出及换账号后旧令牌失效；观看路由矩阵和恰好到期的边界需补验。

### course-access-23

当对连接真实学堂的浏览器执行观看入口系统测试时，测试应点击“开始观看”并核对播放地址获取、视频显示、焦点、面板状态和播放被浏览器拒绝时的提示 [[course-access-13](#course-access-13)]，再通过会话失效、课程取消发布和中断网络分别核对初始申请与续签失败的消息、按钮恢复及登录跳转 [[course-access-15](#course-access-15)]：

- 现有测试未覆盖这些浏览器交互，需补验。
